# Merge Conflict Resolution Guide

## Issue
When trying to pull the latest changes from `copilot/update-personal-website`, you encountered:

```
error: Your local changes to the following files would be overwritten by merge:
	public/sitemap-0.xml
Please commit your changes or stash them before you merge.
```

## What Happened
The `sitemap-0.xml` file is auto-generated by `next-sitemap` during the build process. It was previously tracked in git, which caused conflicts when both local and remote versions differed.

## Solution Implemented
We've added these files to `.gitignore` so they won't be tracked anymore:
- `public/sitemap*.xml`
- `public/robots.txt`

These files are now removed from git tracking but still exist locally and will be regenerated on every build.

## How to Resolve on Your Local Machine

### Option 1: Quick Fix (Recommended)
```bash
# Discard your local changes to the sitemap file
git restore public/sitemap-0.xml

# Pull the latest changes
git pull origin copilot/update-personal-website

# Rebuild to regenerate the sitemap
npm run build
```

### Option 2: If You Want to Keep Your Local Changes
```bash
# Stash your local changes
git stash

# Pull the latest changes
git pull origin copilot/update-personal-website

# Drop the stash (sitemap will be regenerated on build anyway)
git stash drop

# Rebuild to regenerate the sitemap
npm run build
```

### Option 3: Start Fresh
```bash
# Remove the file completely
rm public/sitemap-0.xml

# Pull the latest changes
git pull origin copilot/update-personal-website

# Rebuild to regenerate the sitemap
npm run build
```

## Why This Fixes Future Conflicts
After this change:
- ✅ Sitemap files are automatically regenerated on every build
- ✅ No more git tracking = no more merge conflicts
- ✅ Each developer can have their own local version
- ✅ CI/CD will generate its own version during deployment

## Verification
After pulling and rebuilding, verify everything works:

```bash
# Check that files are ignored
git status  # Should show "nothing to commit, working tree clean"

# Verify sitemap files exist locally
ls -la public/sitemap*.xml

# Start the dev server to test
npm run dev
```

## Summary
This is a one-time fix. After you pull these changes, you'll never encounter this merge conflict again with sitemap files! 🎉
